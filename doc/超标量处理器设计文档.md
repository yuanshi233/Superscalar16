# 乱序超标量处理器 设计文档

**规格：16位寻址 | 16位数据 | 双发射 | 乱序执行 | 顺序提交 | 分布式ROB**

---

## 全局参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 指令字长 | 16 位 | 固定 |
| 数据字长 | 16 位 | |
| 指令存储器 | 64K × 16 位 | 地址 16 位 |
| 数据存储器 | 64K × 16 位 | 地址 16 位 |
| 逻辑寄存器 | 8 个（r0~r7） | r0 恒为 0 |
| 物理寄存器 | 64 个（p0~p63） | p0 恒为 0，6 位地址 |
| 发射宽度 | 双发射 | |
| 执行模式 | 乱序执行，顺序提交 | |
| 分布式 ROB | 3 个，每个 16 项 | 共 48 项，8 位序列号 |
| 保留站 | 3 个，每个 16 项 | ALU0_RS / ALU1_RS / LS_RS |
| BTB | 64 项直接映射 | 索引 pc[5:0]，tag pc[15:6] |
| Store Buffer | 8 项 | |
| CDB | 双 CDB | CDB0 连 ALU，CDB1 连 LS |
| PRF | 64 × 16 位 | 双写端口 |

# 阶段一：取指单元

## 一、功能概述

取指单元负责每个时钟周期从指令存储器取出两条相邻指令，与 PC 值和分支预测标志一起打包送入取指缓冲，供译码阶段使用。

内部包含五个子模块：

- 指令存储器（IMEM）
- PC 寄存器
- PC 更新逻辑（PC 加法器 + PC 选择器）
- 分支目标缓冲（BTB）
- 取指缓冲（FIFO）

---

## 二、指令存储器（IMEM）

| 项目 | 说明 |
|------|------|
| 输入 | `addr[15:0]`，来自 PC 寄存器 |
| 输出 | `instr0[15:0]`，地址 addr 处的指令；`instr1[15:0]`，地址 addr+1 处的指令 |
| 行为 | 纯组合逻辑，地址变化后输出立即变化，无需时钟 |
| 容量 | 64K × 16 位 |

---

## 三、PC 寄存器

| 信号 | 位宽 | 方向 | 说明 |
|------|------|------|------|
| `next_pc` | 16 | 输入 | 下一个 PC 值 |
| `update` | 1 | 输入 | 更新使能，1=更新，0=保持 |
| `clk` | 1 | 输入 | 时钟 |
| `rst` | 1 | 输入 | 复位 |
| `pc` | 16 | 输出 | 当前 PC 值 |

**行为：**

- `rst = 1` 时，`pc` 置为 `0x0000`
- 时钟上升沿，若 `update = 1`，则 `pc = next_pc`
- 时钟上升沿，若 `update = 0`，则 `pc` 保持不变

---

## 四、PC 更新逻辑

包含一个加法器和一个选择器。

### 4.1 PC 加法器

| 项目 | 说明 |
|------|------|
| 输入 | 当前 `pc[15:0]` |
| 输出 | `pc_plus_2[15:0]` = `pc + 2` |
| 实现 | 16 位加法器，一端接当前 PC，另一端接常数 2 |

### 4.2 PC 选择器

**输入信号：**

| 信号 | 位宽 | 来源 | 说明 |
|------|------|------|------|
| `pc` | 16 | PC 寄存器 | 当前 PC |
| `pc_plus_2` | 16 | 加法器 | PC+2 的结果 |
| `predict_taken` | 1 | BTB | 是否预测跳转 |
| `branch_target` | 16 | BTB | 预测的目标地址 |
| `recover_pc` | 16 | 提交仲裁器 | 分支失败恢复的正确 PC |
| `flush` | 1 | 提交仲裁器 | 分支失败冲刷信号 |
| `stall` | 1 | 控制逻辑 | 流水线停顿信号 |

**输出信号：**

| 信号 | 位宽 | 说明 |
|------|------|------|
| `next_pc` | 16 | 下一个 PC 值 |
| `update` | 1 | 是否更新 PC |

**选择逻辑（优先级从高到低）：**

```

if flush = 1:
next_pc = recover_pc
update = 1

elif stall = 1:
next_pc = pc
update = 0

elif predict_taken = 1:
next_pc = branch_target
update = 1

else:
next_pc = pc_plus_2
update = 1

```

---

## 五、分支目标缓冲（BTB）

### 5.1 存储结构

| 属性 | 说明 |
|------|------|
| 项数 | 64 项 |
| 映射方式 | 直接映射，索引 = `pc[5:0]` |
| 每项字段 | `valid`(1 位) + `tag`(10 位) + `target`(16 位) + `counter`(2 位) |
| 总容量 | 64 × 29 = 1856 位 |

**字段含义：**

| 字段 | 位宽 | 说明 |
|------|------|------|
| `valid` | 1 | 该项是否存有有效数据 |
| `tag` | 10 | 记录的分支指令的 `pc[15:6]`，用于匹配确认 |
| `target` | 16 | 上次跳转的目标地址 |
| `counter` | 2 | 2 位饱和计数器，00=强不跳，01=弱不跳，10=弱跳，11=强跳 |

### 5.2 查询规则

每个时钟周期执行：

```

index = pc[5:0]
entry = BTB[index]
hit = (entry.valid == 1) AND (entry.tag == pc[15:6])
predict_taken = hit AND (entry.counter >= 2)
branch_target = entry.target

```

**输出信号：**

| 信号 | 位宽 | 去向 | 说明 |
|------|------|------|------|
| `predict_taken` | 1 | PC 选择器 | 预测是否跳转 |
| `branch_target` | 16 | PC 选择器 | 预测目标地址 |

### 5.3 更新规则

分支指令执行完成后，由执行单元发出更新信号。

```

index = update_pc[5:0]
entry = BTB[index]

if entry.valid == 0:
entry.valid = 1
entry.tag = update_pc[15:6]
entry.target = actual_target
entry.counter = 2

elif entry.tag == update_pc[15:6]:
if actual_taken:
entry.counter = min(entry.counter + 1, 3)
else:
entry.counter = max(entry.counter - 1, 0)
entry.target = actual_target

else:
entry.tag = update_pc[15:6]
entry.target = actual_target
entry.counter = 2

```

**更新输入信号：**

| 信号 | 位宽 | 来源 | 说明 |
|------|------|------|------|
| `update_en` | 1 | 执行单元 | 更新使能 |
| `update_pc` | 16 | 执行单元 | 分支指令的 PC |
| `actual_taken` | 1 | 执行单元 | 实际是否跳转 |
| `actual_target` | 16 | 执行单元 | 实际目标地址 |

### 5.4 复位

所有 `valid` 位清零。

---

## 六、取指缓冲（FIFO）

### 6.1 存储结构

| 属性 | 说明 |
|------|------|
| 容量 | 8 项 |
| 组织方式 | 环形队列，`head` 读指针 + `tail` 写指针 + `count` 计数器 |
| 每项大小 | 50 位 |

**每项内容：**

| 字段 | 位宽 | 说明 |
|------|------|------|
| `instr0` | 16 | 指令字 0 |
| `instr1` | 16 | 指令字 1 |
| `pc` | 16 | 两条指令的起始地址 |
| `pred0` | 1 | 指令 0 的 BTB 预测标志 |
| `pred1` | 1 | 指令 1 的 BTB 预测标志 |

### 6.2 写入操作

条件：`write_en = 1` 且 `count < 8`

- 将 `instr0`、`instr1`、`pc`、`pred0`、`pred1` 写入 `tail` 指向的项
- `tail = (tail + 1) mod 8`
- `count = count + 1`

若 `count = 8`（满），`write_en` 被忽略，数据丢弃。

### 6.3 读出操作

条件：`read_en = 1` 且 `count > 0`

- 将 `head` 指向的项输出到译码阶段
- `head = (head + 1) mod 8`
- `count = count - 1`

若 `count = 0`（空），`read_en` 被忽略。

### 6.4 状态信号

- `empty = (count == 0)`
- `full = (count == 8)`

### 6.5 冲刷

`flush = 1` 时：

- `head = 0`
- `tail = 0`
- `count = 0`

---

| `fifo_empty` | 1 | 缓冲空 |

### 7.3 从提交仲裁器接收

| 信号 | 位宽 | 说明 |
|------|------|------|
| `flush` | 1 | 分支失败冲刷 |
| `recover_pc` | 16 | 恢复用的正确 PC |

### 7.4 从控制逻辑接收

| 信号 | 位宽 | 说明 |
|------|------|------|
| `stall` | 1 | 流水线停顿 |

## 八、内部信号流

```

PC寄存器 → pc → IMEM → instr0, instr1 → 取指缓冲写入
↑              │
│              └→ 加法器 → pc_plus_2
│                       │
│                       ↓
│                   PC选择器 ← BTB查询结果
│                       │
└── next_pc ←───────────┘

取指缓冲 → instr0, instr1, pc, pred0, pred1 → 译码阶段

```

# 阶段二：译码单元

## 一、功能概述

译码单元接收取指缓冲送来的两条 16 位指令字，将其翻译为统一格式的控制信号和数据通路选择信号，同时透传 PC 和分支预测标志，输出给重命名阶段。

两个译码器并行工作，分别处理指令 0 和指令 1。纯组合逻辑，无内部状态，一个周期完成。

---

## 二、输入信号

来自取指缓冲（FIFO），每周期一组：

| 信号名 | 位宽 | 说明 |
|--------|------|------|
| `instr0` | 16 | 指令字 0 |
| `instr1` | 16 | 指令字 1 |
| `pc_in` | 16 | 指令 0 的地址（指令 1 地址为 pc_in+1） |
| `pred0` | 1 | 指令 0 的 BTB 预测标志 |
| `pred1` | 1 | 指令 1 的 BTB 预测标志 |
| `valid` | 1 | 输入有效（FIFO 非空） |

当 `valid=0` 时，译码单元不工作，输出 `valid=0`。

---

## 三、指令格式

16 条指令，16 位定长，四种格式：

**R 型（寄存器-寄存器运算）**
```

[15:12] opcode
[11:9]  rd
[8:6]   rs1
[5:3]   rs2
[2:0]   000

```
指令：ADD, SUB, AND, OR, XOR, SLT

**I 型（立即数运算 / Load / Store）**
```

[15:12] opcode
[11:9]  rd (或基址)
[8:6]   rs1 (或数据源)
[5:0]   imm6

```
指令：ADDI, LW, SW, SLTI, JALR

**B 型（条件分支）**
```

[15:12] opcode
[11:9]  rs1
[8:6]   rs2
[5:0]   imm6

```
指令：BEQ, BNE

**J 型（直接跳转）**
```

[15:12] opcode
[11:9]  rd
[8:0]   imm9

```
指令：JAL

---

## 四、字段提取规则

每个译码器独立从 16 位指令中提取以下字段。

### 4.1 opcode (4 位)
直接取 `instr[15:12]`。

### 4.2 rd_logic (3 位，目的逻辑寄存器号)
| 指令类型 | 取值 |
|----------|------|
| R 型 (ADD/SUB/AND/OR/XOR/SLT) | `instr[11:9]` |
| I 型 (ADDI/LW/SLTI/JALR) | `instr[11:9]` |
| J 型 (JAL) | `instr[11:9]` |
| B 型 (BEQ/BNE) | `000` |
| SW | `000` |
| NOP/HALT | `000` |

### 4.3 rs1_logic (3 位，源寄存器 1)
| 指令类型 | 取值 |
|----------|------|
| R 型 | `instr[8:6]` |
| I 型 (ADDI/LW/SLTI/JALR) | `instr[8:6]` |
| B 型 (BEQ/BNE) | `instr[11:9]` |
| SW | `instr[11:9]` (基址) |
| J 型 (JAL) | `000` |
| NOP/HALT | `000` |

### 4.4 rs2_logic (3 位，源寄存器 2)
| 指令类型 | 取值 |
|----------|------|
| R 型 | `instr[5:3]` |
| B 型 | `instr[8:6]` |
| SW | `instr[8:6]` (存储数据) |
| I 型 / J 型 / NOP / HALT | `000` |

### 4.5 imm16 (16 位，符号扩展立即数)
| 指令类型 | 立即数源 | 扩展方式 |
|----------|----------|----------|
| I 型 (ADDI/LW/SLTI/JALR) | `instr[5:0]` (6 位) | `{ {10{instr[5]}}, instr[5:0] }` |
| SW | `instr[5:0]` (6 位) | 同上 |
| B 型 (BEQ/BNE) | `instr[5:0]` (6 位) | 同上 |
| J 型 (JAL) | `instr[8:0]` (9 位) | `{ {7{instr[8]}}, instr[8:0] }` |
| R 型 / NOP / HALT | - | `16'h0000` |

**控制信号含义：**

| 信号 | 位宽 | 描述 |
|------|------|------|

- `101`：小于比较

## 六、输出信号

每个译码器输出一个 57 位的打包信号，以及指令自身的 PC（16 位）。

### 6.1 指令 0 输出（dec0）

| 字段 | 位宽 | 说明 |
|------|------|------|
| opcode | 4 | 操作码 |
| rd_logic | 3 | 目的逻辑寄存器号 |
| rs1_logic | 3 | 源逻辑寄存器 1 |
| rs2_logic | 3 | 源逻辑寄存器 2 |
| imm | 16 | 符号扩展立即数 |
| reg_write | 1 | 写寄存器使能 |
| mem_read | 1 | 读内存使能 |
| mem_write | 1 | 写内存使能 |
| branch | 1 | 条件分支标志 |
| jump | 1 | 无条件跳转标志 |
| alu_op | 3 | ALU 操作码 |
| alu_src | 1 | ALU 立即数选择 |
| mem_to_reg | 1 | 写回数据选择 |
| halt | 1 | 停机标志 |
| pc0 | 16 | 指令 0 地址（透传） |

### 6.2 指令 1 输出（dec1）
与指令 0 相同，但是 `pc1 = pc_in + 1`，`pred1` 使用输入 pred1。

### 6.3 整体输出
| 信号 | 位宽 | 说明 |
|------|------|------|
| dec0_packet | 57 | 指令 0 完整译码信息 |
| dec1_packet | 57 | 指令 1 完整译码信息 |
| valid | 1 | 输出有效（同输入 valid） |

所有输出送入重命名阶段。

---

## 七、译码流程

每个译码器执行相同的步骤（纯组合逻辑）：

1. **提取 opcode**：`opcode = instr[15:12]`
2. **判断指令类型**，根据 opcode 确定属于 R/I/B/J/SW/NOP/HALT 中的哪一类。
3. **提取寄存器地址**：按照第四节规则，从对应位域取出 `rd_logic`, `rs1_logic`, `rs2_logic`。
4. **符号扩展立即数**：按照第四节规则产生 `imm16`。
5. **查表生成控制信号**：使用 opcode 查找第五节真值表，输出控制信号。
6. **设置 PC**：对于指令 0，`pc0 = pc_in`；对于指令 1，`pc1 = pc_in + 1`。
7. **透传预测标志**：`pred = pred_in`。
8. **打包输出**：将所有字段拼接为 57 位数据包。

# 阶段三：重命名单元

## 一、功能概述

重命名单元接收译码阶段送来的两条指令信息，在一个周期内完成以下工作：

- 通过 RAT 将逻辑寄存器号映射为物理寄存器号（包括源寄存器和目的寄存器旧映射）
- 检测两条指令之间的 RAW 相关性，进行旁路和未就绪标记
- 从空闲列表 FL 分配新的物理寄存器给目的寄存器
- 分配全局序列号 SN
- 打包发射总线和分布式 ROB 写入总线

重命名单元内部包含 RAT 模块、FL 模块、相关性检测逻辑、物理寄存器分配逻辑、序列号分配逻辑。

---

## 二、输入信号

### 2.1 来自译码阶段

每周期两条指令，每条 57 位译码包：

| 信号 | 位宽 | 说明 |
|------|------|------|
| dec0_packet | 57 | 指令 0 译码结果 |
| dec1_packet | 57 | 指令 1 译码结果 |
| valid | 1 | 输入有效 |

### 2.2 来自 RAT

RAT 采用多端口设计，支持同时读取 6 个逻辑寄存器号的映射：

| 信号 | 位宽 | 说明 |
|------|------|------|
| rs1_phys0 | 6 | 指令 0 rs1 的物理寄存器号 |
| rs2_phys0 | 6 | 指令 0 rs2 的物理寄存器号 |
| rd_phys_old0 | 6 | 指令 0 rd 的旧物理映射 |
| rs1_phys1 | 6 | 指令 1 rs1 的物理寄存器号 |
| rs2_phys1 | 6 | 指令 1 rs2 的物理寄存器号 |
| rd_phys_old1 | 6 | 指令 1 rd 的旧物理映射 |

### 2.3 来自 FL

| 信号 | 位宽 | 说明 |
|------|------|------|
| alloc0 | 6 | 分配给指令 0 的空闲物理寄存器号 |
| alloc1 | 6 | 分配给指令 1 的空闲物理寄存器号 |
| fl_avail | 2 | 当前空闲数量是否够用 |

### 2.4 来自各执行单元的 RS/ROB 满信号

| 信号 | 位宽 | 来源 | 说明 |
|------|------|------|------|
| alu0_rs_full | 1 | ALU0 单元 | ALU0 RS 满（16 项全占） |
| alu1_rs_full | 1 | ALU1 单元 | ALU1 RS 满 |
| ls_rs_full | 1 | LS 单元 | LS RS 满 |
| alu0_rob_full | 1 | ALU0 单元 | ALU0 ROB 满（16 项全占） |
| alu1_rob_full | 1 | ALU1 单元 | ALU1 ROB 满 |
| ls_rob_full | 1 | LS 单元 | LS ROB 满 |

### 2.5 序列号计数器

| 信号 | 位宽 | 说明 |
|------|------|------|
| global_sn | 8 | 当前全局序列号，每条有效指令分配一个唯一递增的序号 |

## 三、内部处理流程

### 3.1 读 RAT 映射

```

rs1_phys0 = RAT[dec0.rs1_logic]
rs2_phys0 = RAT[dec0.rs2_logic]
rd_phys_old0 = RAT[dec0.rd_logic]
rs1_phys1 = RAT[dec1.rs1_logic]
rs2_phys1 = RAT[dec1.rs2_logic]
rd_phys_old1 = RAT[dec1.rd_logic]

```

逻辑寄存器 r0 始终映射到物理寄存器 p0，其值固定为 0。

### 3.2 指令间 RAW 相关性检测

**检测 rs1_logic1 和 rd_logic0：**

```

if (dec1.rs1_logic == dec0.rd_logic) 
AND (dec0.reg_write == 1) 
AND (dec0.rd_logic != 0):
rs1_phys1 = rd_phys_new0
rs1_ready1 = 0

```

**检测 rs2_logic1 和 rd_logic0：**

```

if (dec1.rs2_logic == dec0.rd_logic) 
AND (dec0.reg_write == 1) 
AND (dec0.rd_logic != 0):
rs2_phys1 = rd_phys_new0
rs2_ready1 = 0

```

**无相关时：**

```

rs1_ready0 = 1, rs2_ready0 = 1
rs1_ready1 = 1, rs2_ready1 = 1

```

### 3.3 分配物理寄存器

**指令 0：**

```

if dec0.reg_write == 1:
rd_phys_new0 = alloc0
RAT[dec0.rd_logic] = rd_phys_new0
else:
rd_phys_new0 = 0
rd_phys_old0 = 0

```

**指令 1：**

```

if dec1.reg_write == 1:
rd_phys_new1 = alloc1
if (dec1.rd_logic == dec0.rd_logic) AND (dec0.reg_write == 1):
rd_phys_old1 = rd_phys_old0
RAT[dec1.rd_logic] = rd_phys_new1
else:
rd_phys_new1 = 0
rd_phys_old1 = 0

```

### 3.4 分配全局序列号

```

sn0 = global_sn
sn1 = global_sn + 1
global_sn = global_sn + (指令0有效?1:0) + (指令1有效?1:0)

```

### 3.5 功能码生成

| 条件 | func 值 | 说明 | 目标执行单元 |
|------|---------|------|-------------|
| mem_read == 1 | 001 | Load | LS 单元 |
| mem_write == 1 | 010 | Store | LS 单元 |
| branch == 1 | 011 | 条件分支 | ALU0 或 ALU1 |
| jump == 1 | 100 | 无条件跳转 | ALU0 或 ALU1 |
| 其他 | 000 | ALU 运算 | ALU0 或 ALU1 |

### 3.6 指令分发策略

- 指令 0 优先分配 ALU0，指令 1 优先分配 ALU1。
- 若目标 RS 或 ROB 满，则尝试另一个 ALU；若两个都满，指令停顿。

---

## 四、停顿条件

| 停顿条件 | 说明 |
|----------|------|
| fl_avail < 需求量 | 空闲物理寄存器不足 |
| 指令 0 的目标 RS 满 | 无法写入 |
| 指令 0 的目标 ROB 满 | 无法记录 |
| 指令 1 与指令 0 目标相同 RS 但只剩 1 个空位 | 指令 1 停顿 |

## 七、RAT 设计

- 容量：8 项 × 6 位，逻辑寄存器 r0 硬连线到物理寄存器 p0
- 读端口：6 个组合逻辑读端口（支持同一周期读出 6 个不同逻辑号的物理映射）
- 写端口：2 个组合逻辑写端口（指令 0 和指令 1 各自更新 rd 的映射）
- 恢复端口：1 个，来自提交仲裁器的 RAT 恢复通路

---

## 八、空闲列表 FL 设计

- 容量：64 位位图，每位对应一个物理寄存器
- p0 固定为 0（不可分配）
- 分配：两个优先编码器，找出第一个和第二个空闲物理寄存器号
- 释放：来自提交仲裁器的释放请求，将对应位置 1

---

## 九、时序说明

重命名阶段在一个周期内完成所有操作：

1. 同时读取 RAT 的 6 个端口（组合逻辑）
2. 指令间 RAW 相关性检测（并行比较器）
3. 从 FL 获取空闲物理寄存器号，完成目的寄存器分配和 RAT 更新
4. 根据 RS/ROB 满信号判断停顿，分配全局序列号
5. 打包发射总线（60 位）和 ROB 写入总线（42 位）

所有输出在周期末尾锁存，供发射仲裁器在下周期使用。若停顿发生，仅指令 0 的输出有效，指令 1 被保留。

---

# 阶段四：发射仲裁器

## 一、功能概述

发射仲裁器接收重命名阶段打包的两条指令（各 60 位），根据每条指令的功能码（func）以及分布式保留站和分布式 ROB 的满信号，将指令原子性地路由到对应执行单元的保留站和 ROB。

发射仲裁器是一个纯组合逻辑的路由与验证模块，不缓存指令，不改变指令内容。同一周期最多可路由两条指令。

---

## 二、输入信号

### 2.1 来自重命名阶段

| 信号 | 位宽 | 说明 |
|------|------|------|
| issue0 | 60 | 指令 0 的重命名结果 |
| issue1 | 60 | 指令 1 的重命名结果 |
| valid0 | 1 | 指令 0 有效 |
| valid1 | 1 | 指令 1 有效 |

### 2.2 来自各执行单元的 RS 与 ROB 满信号

| 信号 | 位宽 | 来源 | 说明 |
|------|------|------|------|
| alu0_rs_full | 1 | ALU0 单元 | ALU0 RS 已满（16 项全占） |
| alu1_rs_full | 1 | ALU1 单元 | ALU1 RS 已满 |
| ls_rs_full | 1 | LS 单元 | LS RS 已满 |
| alu0_rob_full | 1 | ALU0 单元 | ALU0 ROB 已满（16 项全占） |
| alu1_rob_full | 1 | ALU1 单元 | ALU1 ROB 已满 |
| ls_rob_full | 1 | LS 单元 | LS ROB 已满 |

---

## 三、功能码路由规则

| func 值 | 含义 | 目标执行单元 | 目标保留站 | 目标 ROB |
|---------|------|-------------|-----------|----------|
| 000 | ALU 运算 | ALU0 或 ALU1 | ALU0_RS 或 ALU1_RS | ALU0_ROB 或 ALU1_ROB |
| 001 | Load | LS 单元 | LS_RS | LS_ROB |
| 010 | Store | LS 单元 | LS_RS | LS_ROB |
| 011 | 条件分支 | ALU0 或 ALU1 | ALU0_RS 或 ALU1_RS | ALU0_ROB 或 ALU1_ROB |
| 100 | 无条件跳转 | ALU0 或 ALU1 | ALU0_RS 或 ALU1_RS | ALU0_ROB 或 ALU1_ROB |

---

## 四、ALU 指令分发策略

采用简单双发射分配策略：

- 指令 0 优先映射到 ALU0
- 指令 1 优先映射到 ALU1

当目标单元的 RS 或 ROB 任一满时，视为该单元不可用，尝试另一个 ALU 单元。若两个 ALU 单元均不可用，则该指令停顿。

原子性要求：一条指令只有在目标 RS 和 ROB 同时有空位时才能写入。

---

## 五、路由逻辑

```

alu0_rs_wr_en = 0, alu1_rs_wr_en = 0, ls_rs_wr_en = 0
alu0_rob_wr_en = 0, alu1_rob_wr_en = 0, ls_rob_wr_en = 0
stall_rename = 0

if valid0:
if func0 in {001, 010}:
if (ls_rs_full == 0) AND (ls_rob_full == 0):
ls_rs_wr_en = 1, ls_rob_wr_en = 1
else:
stall_rename = 1
else:
if (alu0_rs_full == 0) AND (alu0_rob_full == 0):
alu0_rs_wr_en = 1, alu0_rob_wr_en = 1
elif (alu1_rs_full == 0) AND (alu1_rob_full == 0):
alu1_rs_wr_en = 1, alu1_rob_wr_en = 1
else:
stall_rename = 1

if valid1 AND (stall_rename == 0):
if func1 in {001, 010}:
if (ls_rs_full == 0) AND (ls_rob_full == 0):
ls_rs_wr_en = 1, ls_rob_wr_en = 1
else:
stall_rename = 1
else:
if (alu1_rs_full == 0) AND (alu1_rob_full == 0):
alu1_rs_wr_en = 1, alu1_rob_wr_en = 1
elif (alu0_rs_full == 0) AND (alu0_rob_full == 0):
alu0_rs_wr_en = 1, alu0_rob_wr_en = 1
else:
stall_rename = 1

```

---

## 六、输出信号

### 6.1 到各执行单元保留站

| 信号 | 位宽 | 去向 | 说明 |
|------|------|------|------|
| alu0_rs_wr_data | 60 | ALU0_RS | 写入 ALU0 RS 的指令数据 |
| alu0_rs_wr_en | 1 | ALU0_RS | 写使能 |
| alu1_rs_wr_data | 60 | ALU1_RS | 写入 ALU1 RS 的指令数据 |
| alu1_rs_wr_en | 1 | ALU1_RS | 写使能 |
| ls_rs_wr_data | 60 | LS_RS | 写入 LS RS 的指令数据 |
| ls_rs_wr_en | 1 | LS_RS | 写使能 |

### 6.2 到各执行单元分布式 ROB

| 信号 | 位宽 | 去向 | 说明 |
|------|------|------|------|
| alu0_rob_wr_data | 42 | ALU0_ROB | 写入 ALU0 ROB 的指令信息 |
| alu0_rob_wr_en | 1 | ALU0_ROB | 写使能 |
| alu1_rob_wr_data | 42 | ALU1_ROB | 写入 ALU1 ROB 的指令信息 |
| alu1_rob_wr_en | 1 | ALU1_ROB | 写使能 |
| ls_rob_wr_data | 42 | LS_ROB | 写入 LS ROB 的指令信息 |
| ls_rob_wr_en | 1 | LS_ROB | 写使能 |

| 信号 | 位宽 | 去向 | 说明 |
|------|------|------|------|
| stall_rename | 1 | 重命名单元 | 有指令因目标 RS/ROB 满而无法路由 |

---

## 七、时序说明

- 发射仲裁器为纯组合逻辑
- RS 和 ROB 的写使能完全同步，不存在指令只写入 RS 而未写入 ROB 的情况
- stall_rename 信号在当周期产生，重命名阶段在下周期检查该信号

# 阶段五：分布式保留站、执行单元与分布式 ROB

## 一、功能概述

本阶段包含三个独立的执行单元：ALU0 单元、ALU1 单元和 LS 单元。每个执行单元内部集成了保留站（RS）、执行单元（ALU 或 LS）和分布式 ROB。

- 保留站（RS）：16 项，缓存待发射指令，监听 CDB 捕获操作数，操作数就绪后发射到执行单元
- 执行单元：完成算术逻辑运算或 Load/Store 访存
- 分布式 ROB：16 项环形队列，记录指令状态，接收 CDB 更新，向提交仲裁器报告头部信息

---

## 二、ALU0 单元与 ALU1 单元

### 2.1 保留站（ALU_RS）

16 项，每项字段：

| 字段 | 位宽 | 说明 |
|------|------|------|
| busy | 1 | 条目占用 |
| opcode | 4 | 操作码 |
| Vj | 1 | 操作数 1 就绪 |
| Vk | 1 | 操作数 2 就绪 |
| Qj | 6 | 操作数 1 等待的物理寄存器号 |
| Qk | 6 | 操作数 2 等待的物理寄存器号 |
| data_j | 16 | 操作数 1 的值 |
| data_k | 16 | 操作数 2 的值 |
| imm | 16 | 立即数 |
| rd_phys | 6 | 目的物理寄存器号 |
| sn | 8 | 全局序列号 |
| func | 3 | 功能码 |
| pc | 16 | 指令地址 |
| branch_target | 16 | 分支目标地址 |

**CDB 监听**：每项独立监听双 CDB。若 Vj=0 且 Qj 匹配 CDB 上的物理寄存器号，则捕获数据；Vk 同理。

**发射条件**：busy=1，Vj=1，Vk=1，执行单元空闲。

### 2.2 执行单元（ALU）

16 位算术逻辑运算，支持加法、减法、按位与、按位或、按位异或、小于比较。

执行完成后，输出结果到 CDB 仲裁器，同时更新本单元 ROB 对应条目（done=1, result=...）。

### 2.3 分布式 ROB（ALU_ROB）

16 项环形队列，每项字段：

| 字段 | 位宽 | 说明 |
|------|------|------|
| valid | 1 | 条目有效 |
| done | 1 | 执行完成 |
| opcode | 4 | 操作码 |
| rd_phys_old | 6 | 旧物理映射 |
| rd_phys_new | 6 | 新物理映射 |
| rd_logic | 3 | 逻辑目的寄存器号 |
| reg_write | 1 | 写使能 |
| is_branch | 1 | 分支标志 |
| branch_pred | 1 | 预测方向 |
| branch_actual | 1 | 实际方向 |
| pc | 16 | 指令地址 |
| sn | 8 | 全局序列号 |
| branch_target | 16 | 分支目标地址 |
| result | 16 | 执行结果 |

---

## 三、LS 单元

### 3.1 LS 保留站（LS_RS）

与 ALU_RS 结构相同，16 项。

### 3.2 LS 执行单元

- 地址计算：16 位加法器计算 base_addr + offset
- Load：读 DMEM，结果上 CDB1
- Store：将地址（16 位）、数据（16 位）、sn（8 位）写入 Store Buffer

### 3.3 Store Buffer

8 项，每项字段：

| 字段 | 位宽 | 说明 |
|------|------|------|
| valid | 1 | 条目有效 |
| addr | 16 | DMEM 写入地址 |
| data | 16 | 写入数据 |
| sn | 8 | 对应 Store 指令的序列号 |

**Store-to-Load 转发**：Load 指令在执行时，先扫描 Store Buffer 所有有效条目。若地址匹配，直接取 Store Buffer 中的最新数据，不读 DMEM。

### 3.4 LS 分布式 ROB（LS_ROB）

与 ALU_ROB 结构相同，16 项。额外字段：

| 字段 | 位宽 | 说明 |
|------|------|------|
| is_store | 1 | 是否为 Store 指令 |
| store_addr | 16 | Store 目标地址 |
| store_data | 16 | Store 数据 |

---

## 四、CDB 交互

双 CDB 架构：

- CDB0：连接 ALU0 和 ALU1，优先级 ALU0 > ALU1
- CDB1：连接 LS 单元，独占

两条 CDB 同时广播，目标包括 PRF（双写端口）、所有 RS、所有 ROB。

---

## 五、提交仲裁器交互

提交仲裁器持续监视三个分布式 ROB 的头部信息，选择 done=1 且序列号最小的指令提交。

---

## 六、冲刷处理

当提交仲裁器发出 flush=1 和 flush_sn：

- 所有 RS 清除 sn > flush_sn 的条目（busy=0）
- 所有 ROB 清除 sn > flush_sn 的条目（valid=0），Tail 指针回退
- Store Buffer 清除 sn > flush_sn 的条目（valid=0）

---

# 阶段六：CDB 仲裁器与物理寄存器堆

## 四、物理寄存器堆（PRF）

- 容量：64 × 16 位
- p0 固定为 0，硬连线
- 双写端口：来自 CDB0 和 CDB1
- 读端口：重命名阶段有专用"冷读取"端口

# 阶段七：提交仲裁器与全局冲刷

## 一、功能概述

提交仲裁器是分布式 ROB 架构的顺序提交核心，负责：

- 监视三个分布式 ROB 的头部条目
- 选择 done=1 且序列号最小的指令提交
- 释放旧物理寄存器
- 触发 Store 写 DMEM
- 检测分支预测失败，发起全局冲刷与 RAT 恢复

---

## 二、输入信号

来自三个分布式 ROB 的头部信息，每个 ROB 提供：

| 信号 | 位宽 | 说明 |
|------|------|------|
| rob_head_valid | 1 | 头部有效 |
| rob_head_done | 1 | 头部完成 |
| rob_head_sn | 8 | 头部序列号 |
| rob_head_rd_phys_old | 6 | 旧物理寄存器号 |
| rob_head_reg_write | 1 | 写寄存器 |
| rob_head_is_branch | 1 | 分支标志 |
| rob_head_branch_pred | 1 | 预测方向 |
| rob_head_branch_actual | 1 | 实际方向 |
| rob_head_pc | 16 | 指令 PC |
| rob_head_branch_target | 16 | 分支目标地址 |
| rob_head_result | 16 | 结果数据 |

LS_ROB 额外提供：`is_store`, `store_addr`(16), `store_data`(16)。

---

## 三、提交流程

```

candidate_valid = false
min_sn = 最大可能值

for each ROB:
if rob.head_valid AND rob.head_done:
if rob.head_sn < min_sn:
min_sn = rob.head_sn
candidate_valid = true

if candidate_valid:
提交该指令：
1. 若 reg_write：释放 rd_phys_old 到 FL
2. 若 is_store：触发 Store Buffer 写 DMEM
3. 若 is_branch 且 branch_pred != branch_actual：触发全局冲刷
4. 弹出 ROB 头部

```

---

## 四、分支预测失败与全局冲刷

### 4.1 触发条件

`is_branch == 1` 且 `branch_pred != branch_actual`

### 4.2 冲刷操作

- 所有 ROB：清除 sn > flush_sn 的条目，Tail 回退
- 所有 RS：清除 sn > flush_sn 的条目
- Store Buffer：清除 sn > flush_sn 的条目
- 取指缓冲：清空
- RAT 恢复：从被清除 ROB 条目中逆序恢复旧映射
- PC 恢复：`recover_pc = branch_actual ? branch_target : pc+2`

---

## 五、输出信号

**到 ROB：** commit 信号 + commit_sn
**到 FL：** free_phys(6), free_valid(1)
**到 LS 单元：** store_commit(1), store_commit_sn(8)
**全局冲刷：** flush(1), flush_sn(8), recover_pc(16)

---

# 阶段八：数据存储器与 Store Buffer

## 一、数据存储器（DMEM）

| 参数 | 规格 |
|------|------|
| 容量 | 64K × 16 位 |
| 地址宽度 | 16 位 |
| 数据宽度 | 16 位 |
| 读端口 | 1 个（组合逻辑） |
| 写端口 | 1 个（时钟沿写入） |

---

## 二、Store Buffer

8 项，每项：valid(1), addr(16), data(16), sn(8)。

**Store-to-Load 转发**：Load 指令在执行时，先扫描 Store Buffer 所有有效条目。若地址匹配，直接取数据，不读 DMEM。

---

## 三、DMEM 读写仲裁

提交写优先于 Load 读。若同一周期冲突，Load 延迟一个周期。
